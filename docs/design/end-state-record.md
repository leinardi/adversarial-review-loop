# What Rule 4 does and does not guarantee, and the end-state record

The long form of Rule 4 in [`AGENTS.md`](../../AGENTS.md): the two escapes that defeat it, what reporting still guarantees, and how the `ended_*` record bounds both reports to the activation's own lifetime.

## Rule 4, in full

**The user owns the exits.** `implement`, `finish`, `stop`, `resume`, `config`, `accept` and `pause` are `disable-model-invocation: true`, and Claude's own route to `finish`, `deactivate` (the escape `stop` runs), `resume`, `config`, `accept` and `pause` — Bash — is denied in `commands/pretool.py`. `pause` is here because it decides whether the Stop gate keeps asking for the remaining phases: reachable by Claude it would be an unbounded, strictly better `defer`, and `defer` is bounded by `max_defers` precisely because "stop asking me for more" is also the shape of an agent that has stopped making progress. `accept` is the one of these that grants something rather than only ending or adjusting the activation — see `commands/accept.py` for why binding it to one exact tree hash is what keeps it from being able to pre-approve anything else. See below for what Rule 4 does and does not guarantee.

## What Rule 4 does and does not guarantee

The denial reads `tool_input.command` as a string, so it stops the direct route and nothing more. Two things defeat it, both confirmed by experiment:

- **A wrapper.** `bash escape.sh`, where the script commits and then runs `arl.sh deactivate`, is recognised as neither a commit nor an escape. The commit lands unreviewed and the mode ends.
- **Editing the state.** `status: DISARMED` written straight into `state.json` ends the mode with no command to inspect at all. The `PreToolUse` gate now refuses an *editing tool* aimed at the state root, but a shell command can still write the same file — the gate runs as the same user, and by the time it is asked about a command, that command is about to run.

**So Rule 4 is not enforceable against a deliberately adversarial model.** It holds against mistakes, drift, and a model following the loop's instructions, which is what the component is for. No file-based mechanism can do better: any token this plugin writes to disk, the model's shell can write too.

What *is* enforceable is reporting. `confirm-commit` reports a HEAD whose tree no review approved, and the Stop gate repeats it through `systemMessage`. The value of that second channel rests on `systemMessage` reaching the *user*, so that relaying it is not the model's decision — **that is assumed, not verified**, and it is `tests/STEP0.md` item 12. If it turns out to be model-visible only, this paragraph is wrong and the escape has no reliable reader at all. Closing the rule properly needs a host-only signal that a real user typed the slash command: item 11. Until both are settled, the limit stands as documented rather than fixed.

**Both reports are bounded to the activation's own lifetime, and the bound is what makes them readable.** Each of the three terminal transitions (`session.deactivate`, `completion.Completion.commit`, `resume`'s retirement) folds `hooks.ended_evidence` into the *same* `state.update` as its status write, and `stop._ended` / `posttool._guard_ended_head` report from that record instead of from current HEAD. Before that they asked "is current HEAD approved?", which is not a question about this gate at all: an ordinary commit made after the mode ended was indistinguishable from the wrapper escape, so the alarm fired on every turn end and every Bash call forever — which is the same as carrying no information. Four things must stay stated at their real width, and `docs/edge-cases.md` ("After the mode ends") is the long form:

- **Detection is exactly "the recorded tree is absent from `approved_trees`".** Not proof of review, not proof of commit identity — the same `approved_trees` caveat the bypass path already carries at `docs/security.md`, and an empty commit or a rewrite onto an approved tree is silent.
- **The capture is not atomic with git.** The activation lock does not lock the repository, so a commit landing between the capture and the transaction's save is uncovered. The head/tree pair is at least self-coherent: the tree is derived from the captured commit (`<head>^{tree}`), never read from `HEAD` twice.
- **`deactivate && commit`, in that order, records an approved tree and is silent.** Conceded, like the two escapes above. The old code "caught" it only by also firing on every legitimate post-stop commit.
- **The state-edit escape is caught one step removed, and legacy documents are the exception.** A terminal document that carries the `ended_*` fields *present and empty* cannot have reached that status through any of the three transitions, so it is reported as an edited `state.json`. A document where they are **absent** ended before the record existed, and both channels stay silent — `/adversarial-review-loop:status` answers for those on request, user-invoked, writing nothing. The absent case is narrowed to genuinely-old activations by `_migrate`'s 4 → 5 arm plus `pretool._upgrade_stale_document`; see `STATE_VERSION` in [`state-fields.md`](state-fields.md).
