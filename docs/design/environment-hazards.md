# Known environment hazards

The long form of the environment hazards in [`AGENTS.md`](../../AGENTS.md): the things outside the gate that change what it sees.

- `--pure` removes OpenCode **plugins**, not global skills (`~/.config/opencode/skills`) or a global `~/.config/opencode/AGENTS.md`. Both still reach the reviewer; the fixed prompts tell it to ignore ambient style directives and not to invoke a skill for the review. A reformatted review fails the contract, which blocks — it never approves.
- Anything that writes into the worktree between the gate and the commit (an editor writing back a buffer, an MCP server dropping a state directory, a file watcher) changes the tree out from under the approval and lands you in `RECONCILE`. Gitignore such paths before arming.
- The snapshot's throwaway index is a **copy of the repository's real index**, mtime included but mode deliberately not (`gitsnap._seed`; the file sits in `$TMPDIR` and a repository index is commonly group-readable, so it keeps `mkstemp`'s `0600`). Both parts are load-bearing: seeding from `HEAD` instead loses index entries `git add -A` would not recreate — a `git add -f` of a gitignored path is the ordinary way to have one — and a copy stamped with the current time defeats git's racy-clean re-read, which is what catches a same-size rewrite made in the same second as the last `git add`. Either way the reviewed tree stops being the tree the commit will have, and a correct commit lands in `RECONCILE`.
- A diverging **root** commit has no parent, so `git reset --soft` has no target that exists. Its recovery is a bounded `git update-ref -d HEAD` (`pretool._gate_root_undo`), permitted only while `bad_commit_parent` is empty, `activation_commit` is empty, `HEAD` is still `bad_commit`, and git confirms `HEAD` has no parent. Every other `git update-ref` is denied, **including the dashed executable**: git still ships `git-update-ref` in `git --exec-path` (measured: git 2.55), and `/usr/lib/git-core/git-update-ref -d HEAD` deletes the branch ref just as the subcommand does, so `_UPDATE_REF_RE` matches both spellings and `head_ref_deletion` then accepts only the canonical one. Do not describe the reset as the only recovery; an activation armed in an empty repository reaches this on its first phase.
- An activation armed on an **unborn HEAD** can never take the no-review completion path: `completion.phase_progress_gap` refuses a chain with no `activation_commit` to anchor it, and no question asked of git can confirm that emptiness (report 038). It must not *escalate* on that, though — `NEEDS_HUMAN` is neither finishable nor resumable, and `accept` refuses once `phase` is past the last phase, so all three remedies the escalation named were themselves refused and only `stop` remained (measured on a real 12-phase activation). The Stop gate therefore refuses to complete while staying `ACTIVE`, names `finish` and `stop`, and `arm` warns at phase 0. A **blanked** anchor in a repository that has history is a different thing and still escalates; git tells them apart, because the benign case's phase 1 is a root commit. Do not collapse the two, and do not report either as "unexpected state" — every gap now names itself.
- **Every detector knows the dashed spelling**, not only `update-ref`. git installs `git-commit`, `git-reset` and `git-update-ref` in `git --exec-path` (measured: git 2.55) and each does exactly what its subcommand does, so `_COMMIT_RE`, `_RESET_RE` and `_UPDATE_REF_RE` all carry the `(…{_SPACE}+|-)` alternative. Detection stays deliberately looser than the validators: a dashed or path-qualified spelling reaches the gate and is then refused by `validate_commit` / `reset_target` / `head_ref_deletion`, which accept only the canonical `git <subcommand>` form. The right-hand boundary is what keeps `git commit-graph` and `git-commit-graph` out of it — a new detector needs both halves, or it is either a bypass or a false positive.
- `confirm-commit` reports an **unborn HEAD** when `activation_commit` is non-empty (`posttool._guard_unreviewed_head`). That is the one HEAD move the tree comparison cannot make: a deleted branch ref leaves no tree to compare, and an unborn HEAD is *also* the armed state of a repository with no commits, so reading the two as the same thing made a destroyed history silent.
